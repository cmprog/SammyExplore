# Event catalog (the contract between systems)

Every bus event goes here. To add an event, add it to this file in the same change.
Payloads are plain data (they get cloned). Owner = the system that emits it.
`emit(name, data, {quiet: true})` skips the clone and the debug ring buffer (`__sammy.events`); use it only for
high-frequency events (currently `narrator:blip`). Quiet events still reach every listener.

| Event | Payload | Owner | Notes |
|---|---|---|---|
| `scene:change` | `{from, to, kind}` | SceneManager | `kind`: `change` (whole stack replaced), `push` (overlay opened, e.g. `pause`), `pop` (overlay closed). `from`/`to` are the top scene before/after |
| `level:start` | `{levelId, name, environment, timeOfDay, size, checkpointId}` | playing scene | after the level is built; `size` = `{x, y}` in tiles. `environment` = the level's environment (`data/environments.js`, e.g. `outdoor`, `bedroom`); `timeOfDay` is set outdoors and `null` indoors. `checkpointId` = the checkpoint a Continue resumed at, `null` on a fresh start (so intros can stay quiet on Continue) |
| `level:loadFailed` | `{levelId, message}` | playing scene | the level could not be fetched or built; main.js returns to the title with a gentle notice |
| `level:complete` | `{...zoneProps, id, levelId, nextLevel?, door?}` | LevelLoader (exit zone) | `id` = exit zone id (required in data; a save key); once per level load. `nextLevel` = the exit's own `nextLevel`, else the level data's; absent on the last level of a chapter, which goes home to the bedroom (the save then says `bedroom`). Autosaved by SaveSystem; opens the level complete overlay. An exit door (a door with `exitId`) fires the same exit path when it finishes opening: `id` = its `exitId`, `door` = the door's id |
| `checkpoint:reached` | `{id, levelId, pos}` | LevelLoader | `id` = checkpoint zone id; once per level load. Autosaved by SaveSystem. Not re-sent for a checkpoint restored by Continue |
| `correction:triggered` | `{...zoneProps, id, levelId}` | LevelLoader | Sammy is somewhere silly. `id` = zone id (`world-bottom` for falling off the world); optional `lineId`, `reason` |
| `correction:reset` | `{zoneId}` | Narrator | midpoint of the rewrite effect. The playing scene moves the player to `level.respawn`. Also sent immediately (no visuals) if the narrator is disposed/reloaded mid-correction and the reset hadn't gone out yet |
| `correction:done` | `{zoneId}` | Narrator | input unlocked. Also sent immediately (no visuals) on dispose/reload mid-correction. A `correction:triggered` arriving while a correction runs is ignored by the narrator; on `correction:done` the playing scene re-arms correction zones so one the player is still inside fires again |
| `narration:zone` | `{key, id, levelId}` | LevelLoader | |
| `daycycle:phase` | `{phase}` | DayCycle | indoor levels with a day/night cycle (the bedroom). `phase`: `dawn`, `day`, `dusk`, or `night`. Sent once when the room is set up (the phase the visit starts in, right after `level:start`), then whenever the phase changes, including after `__sammy.commands.setTimeOfDay` |
| `daycycle:nightlight` | `{on}` | DayCycle | the nightlight switched on (`on: true`, in the evening) or off (in the morning), at `nightlight.on` / `.off` in `data/dayCycle.js`. Only on a change (including a `__sammy.commands.setTimeOfDay` jump across it), never when the room is set up: a visit that starts at night just has it on. RoomLighting reads the cycle directly; this is for the narrator |
| `narrator:blip` | `{lineId}` | Narrator | typewriter tick; emitted quietly (kept out of the debug event ring) |
| `narrator:line` | `{id, text}` | Narrator | a line started showing |
| `narrator:revealed` | `{id}` | Narrator | the showing line is fully revealed (typed out, or skipped to the end). The level complete overlay waits for it before offering to continue. The narrator also hears it itself: a line with trigger `narrator:revealed` and `key` = another line's id follows that line (the bedroom's cast-list gag) |
| `narrator:skip` | none | any (level complete overlay) | finish revealing the showing line now (no-op if nothing is typing). For screens that take the confirm press while a line is still typing |
| `player:jump` | none | Sammy | |
| `player:flap` | `{chargesLeft}` | Sammy | |
| `player:flapEmpty` | none | Sammy | tried to flap with 0 charges |
| `player:glideStart` | none | Sammy | |
| `player:glideEnd` | none | Sammy | **any** exit from glide (release, flap, land, reset) |
| `player:land` | `{impact}` | Sammy | impact is fall speed (0..1), so soft landings can sound softer |
| `interact:<type>` | `{id, ...}` | Interaction | E pressed with that interactable nearest and in range; emitted before its `interact()` runs. The payload is the interactable's `interactPayload()`. Types so far: `interact:door` `{id}`, `interact:sign` `{id, key}` (`key` = the sign's narration key, so a line with that `key` "reads" it), `interact:twyx` `{id}` (Twyx the cat; Audio meows. In a level with `companionHub: true` the Companion system treats it as asking her along or letting her stay, see `companion:*`; everywhere else it is just a pet), `interact:lever` `{id}` (the lever then emits `mechanism:toggle` or `mechanism:cycle`, which Audio clunks on), `interact:catspot` `{id, ability, key?}` (a cat spot, T-016: the CatSpots system answers with `catspot:noCat`, `catspot:wrongCat`, or the companion walking over to do `ability`; Audio plays a soft cushion pat). An E press the narrator used to skip/dismiss a line is never an interaction |
| `interact:nothing` | none | Interaction | E pressed with nothing in range |
| `interact:doorLocked` | `{id}` | Door | after `interact:door`, when the door is locked |
| `door:open` | `{id}` | Door | when the open animation starts (plays the creak) |
| `mechanism:toggle` | `{id, on, targets, by?}` | any trigger (Lever, CatSpot, an Upset with its own targets) | the **activation API**: Mechanisms (the level's registry) calls `setActive(on)` on each target id. `id` = the trigger. A lever emits it when thrown (not at level start: a `startsOn` lever snaps its targets silently). Audio plays the lever clunk, except for `by: 'catspot'` (a cat spot's ability has its own sounds) and `by: 'upset'` (an upset thing that calmed down doing its job; its calm sound plays). A `startsOn` lever's silent snap also snaps the targets' own `targets` (an Upset placed already calm). **The targets' state is the truth**: a toggle lever counts as on exactly when all its targets are active, re-reads that before every throw and sends the opposite, and its handle shows it, so triggers sharing a target never drift |
| `mechanism:cycle` | `{id, targets}` | any trigger (a Lever in `cycle` mode; T-017's portal lever) | Mechanisms calls each target's `cycle()`, or flips it if it has none. Sent on every throw; Audio plays the lever clunk |
| `portal:select` | `{chapterId, changed}` | Portal | the portal lever was thrown (its `mechanism:cycle` reached the portal): the portal now shows `chapterId`, the next unlocked chapter (`data/chapters.js` order). `changed: false` when no other chapter is unlocked, so it stays put (the narrator can comment; Audio plays a quieter fizzle). Chapters remembers the pick for this session (not saved) |
| `portal:enter` | `{chapterId, levelId, pos}` | Portal | Sammy stepped into the swirl; once per level load. `pos` = the middle of the opening (world). main.js runs the swirl transition (systems/SwirlTransition.js) into `levelId` at its spawn; the companion comes along. Autosaved by SaveSystem (a real chapter, into a story in progress): Continue starts that chapter. If no trip starts (e.g. a pause opened on the same step) the portal re-arms when Sammy steps out, or after `PORTAL.REARM_AFTER` s. Audio whooshes |
| `chapter:complete` | `{chapterId, unlocked}` | Chapters | a `level:complete` in a chapter's end level (its `endLevelId`, else its `levelId`), sent right after it; also when a finished chapter is replayed. `unlocked` = chapter ids this opened for the first time. SaveSystem adds them to `completedChapters` / `unlockedChapters` (test chapters are never saved; a replay that changes nothing writes nothing) |
| `bridge:move` | `{id, down}` | Bridge | it actually starts lowering (`down: true`) or raising. A bridge never raises while anyone stands on it, so a raise is announced when it finally goes up. Not sent for a silent snap at level start |
| `gate:move` | `{id, open}` | Gate | it starts opening or closing |
| `lift:move` | `{id, toward}` | Lift | it sets off; `toward` = `'a'` or `'b'` (its first or second point). Plays the wind-up hum |
| `lift:arrive` | `{id, at}` | Lift | it reached an end (`'a'`/`'b'`) |
| `lift:held` | `{id}` | Lift | **debug/test only: no game system listens** (playtests and `__sammy.events` read it). It stopped because the next step would push into someone it isn't carrying; once per hold (it carries on by itself when they move) |
| `companion:join` | `{cat}` | Companion | only in a companion hub level (level data `companionHub: true`, the bedroom): E on a cat who isn't the companion, and she comes along. `cat` = her id in `src/data/cats.js` (e.g. `'twyx'`), not the level entity id. One at a time: the previous companion gets `companion:leave` first (refused, so E is a pet, if the current companion is a visitor the hub doesn't place). Autosaved by SaveSystem |
| `companion:leave` | `{cat}` | Companion | only in a companion hub, and only for a cat that hub places (her home): E on the companion lets her stay and roam there. A visitor is never left behind (E is a pet); outside hubs E is always a pet. Autosaved by SaveSystem |
| `companion:waiting` | `{cat, reason}` | Companion | she stopped where Sammy's trail needs something she can't do (not sent while she's on a cat spot errand: `catspot:unreachable` instead). Sent once per hold-up: not again for the same reason until she has made progress (so a stuck re-try never repeats it). `reason`: `gap` (a gap too wide, or a bridge still up/in the way) \| `ledge` \| `gate` \| `door` \| `lift`. She re-checks often, including for a plain walk to Sammy, and carries on by herself when the way opens. Audio plays a "mrrp?" |
| `companion:caughtUp` | `{cat, via}` | Companion | she is back beside Sammy after being apart. `via`: `walked` (made her own way after waiting), `met` (Sammy came back to her), `correction` (put down beside him at the respawn under the page; she trots in once it lifts), `checkpoint` (left behind and Sammy reached a checkpoint: she comes in only when both where she was and where she appears are out of view, retrying as he moves; after `COMPANION.FETCH_FALLBACK_AFTER` s with no such spot, from just off the current screen, or under a sub-second page flip with no input lock. A fetch starts at a checkpoint: put one after every gate, bridge or lift. Waiting at something Sammy can fix (gate, bridge, gap, lift) is never fetched otherwise. Safety net only: stuck for good (inside something solid, in a keep-clear zone such as a gateway or an upset thing's cell, or with nothing under her) out of his sight for `COMPANION.STRANDED_FETCH_AFTER` s starts one too, also `via: 'checkpoint'`), `arrived` (level start, a level change or Continue), `regroup` (below-the-world safety net, also brought in unseen; or debug). Audio chirps |
| `catspot:noCat` | `{spotId, ability, key?}` | CatSpots | E at a cat spot (`interact:catspot`) with no companion. `key` = the spot's optional narration key. The narrator's soft hint; never says which cat it wants |
| `catspot:wrongCat` | `{spotId, ability, cat}` (+ `key?`) | CatSpots | E at a cat spot with a companion who doesn't have its `ability` (`data/abilities.js`). `cat` = the companion's cat id |
| `catspot:unreachable` | `{spotId, ability, cat, reason}` (+ `key?`) | CatSpots | the right cat set off for the spot but has to wait on the way (`reason` as in `companion:waiting`). Once per errand. While she's on an errand this is the ONLY waiting cue: the Companion does not send `companion:waiting` then (she still mrrps), so the narrator never says two things. She carries on by herself if the way opens; if Sammy goes more than `CATSPOT.GIVE_UP_DISTANCE` from the spot first, the errand is called off and she follows him |
| `ability:start` | `{ability, cat, spotId}` | CatSpots | the right cat reached the spot and begins her ability animation. Audio plays the ability's `sounds.start` (Comfort: a purr) |
| `ability:used` | `{ability, cat, spotId}` (+ `key?`) | CatSpots | the moment it works (the ability's `effectAt`). Sent just before the spot's `mechanism:toggle {by: 'catspot'}` drives its targets. Audio plays `sounds.used` (Comfort: a soft chime). Called off before this moment (a correction, a checkpoint fetch bringing her back to Sammy, `companion:caughtUp`, Sammy wandering off, a companion change): nothing is sent but `ability:cancel` (if she had started) |
| `ability:cancel` | `{ability, cat, spotId}` | CatSpots | an ability that had started (`ability:start`) was called off before it worked. Audio stops its start sound (the purr); its targets are unsoothed. The Companion never moves a cat while she performs |
| `upset:calmed` | `{id, kind}` | Upset (e.g. the wind-up mouse) | an upset thing finished calming down (after its own `mechanism:toggle {by: 'upset'}`, if it has targets). `kind` = its entity type (e.g. `windupMouse`); Audio picks its sound from `UPSET_CALM_SOUNDS` in `data/sounds.js`. Not sent for a silent snap at level start |
| `collectible:found` | `{id, kind, levelId}` | Collectible | Sammy touched a find (T-018: the practice course's toy star, `kind: 'toyStar'`; a placeholder for the hat collectibles). Once per level load: it celebrates and is gone. Not saved yet: it is back on the next visit. Audio plays a twinkly chime; a narrator line can use the find's `id` as its key |
| `menu:move` | none | menu scenes (Menu.js) | selection changed |
| `menu:select` | none | menu scenes (Menu.js), level complete | item activated, slider adjusted, or celebration continued |
| `audio:setVolume` | number | any (pause menu) | |
| `audio:setMuted` | boolean | any | |
| `audio:toggleMute` | none | any | |
| `audio:changed` | settings object | Audio | |

Mechanism state (levers, bridges, gates, lifts, cat spots and upset things) and finds (`collectible:found`) are not saved: every level load rebuilds them as placed in the level data. A correction respawn keeps the level, so they keep their state. See `src/systems/Mechanisms.js`.

Save in localStorage `sammyexplore.save` (SaveSystem owns it), schema v2: `{schemaVersion, levelId, checkpointId, reachedCheckpoints, flags, catsRescued, companion, unlockedChapters, completedChapters, updatedAt}`. `companion` = the cat id along with Sammy, or null. v1 saves (M1, live) migrate by adding `companion: null`. `unlockedChapters` / `completedChapters` (T-017) are additive v2 fields, because v2 was already live: a save without them gets them from its `levelComplete.<level>` flags (a finished Chapter One stays finished), and one parked at the start of a chapter it had finished (the old end-of-game spot) continues in the bedroom. Unknown chapter ids are dropped on load.

The companion is not tied to a level: she arrives with Sammy in every level (a level that places her own cat entity uses that one). Mechanism state rules above apply to her too (a lift carries her, a bridge holds her, a gate blocks her).

Settings in localStorage `sammyexplore.settings`: `{volume, muted, musicVolume, sfxVolume}`. Audio owns these keys. Other systems merge, never overwrite.

**The one read-only query exception:** menus may import `getAudioSettings()` from `src/systems/Audio.js` to show the current
sound state when they open (PauseScene does). It returns a copy and changes nothing. Changes still go only through the
`audio:*` events, and later updates come from `audio:changed`. Every other cross-system read goes through the bus.

Coordinates: level data (zone rects, entity x/y) uses tile column/row from the top-left of the map. Everything at runtime (events, `__sammy`, teleport) uses world space with y pointing up.

Narrator line triggers `idle:N`, `spam:<event>`, `ignored:<id>`, and `followed:<id>` are internal to the Narrator. They are not bus events.
